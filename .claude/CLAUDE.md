# Ultimate 3D Testimonial Slider

WordPress plugin (published on wordpress.org) that adds a Testimonial custom post type and renders testimonials via the `[uts]` shortcode as a 3D Swiper coverflow slider, a grid, or a list.

- Prefix / text domain / CPT slug: `uts`
- Requires PHP 5.6+, so don't use newer PHP syntax (no typed properties, arrow functions, `??=`, etc.).
- JS/CSS are built with `@wordpress/scripts`: sources in `src/{frontend,admin,admin-app}/` (entries in `webpack.config.js`), output in `build/` (gitignored). Run `npm run build` (or `npm start` to watch) after editing `src/`; `npm run plugin-zip` makes the release zip (`.distignore`). PHP enqueues entries via `uts_register_build()`, which reads `build/*.asset.php`. No Composer.
- Local dev site: `D:\server\www\learn` (a local WordPress install). The plugin lives in its `wp-content/plugins/` directory.

## Layout

- `ultimate-3d-testimonial-slider.php`: plugin header, `UTS_*` constants, `require_once`s `includes/functions.php` and each `includes/class-*.php`, points the activation/deactivation hooks at `UTS\Plugin::activate()`/`deactivate()`, and calls `UTS\Plugin::instance()->boot()`.
- `includes/class-plugin.php` (`UTS\Plugin`): creates each component once (list in `component_classes()`) and calls its `register()`. `Plugin::instance()->component( 'UTS\Menu' )` returns a booted component (for callbacks or `remove_action()`). Activation registers the CPT, flushes rewrite rules and sets `uts_activation_redirect`.
- `includes/functions.php`: global helpers and the public API (no namespace). Public: `uts_get_settings( $key = null )`, and the 1.0.1 back-compat wrappers `uts_shortcode( $atts )` and `uts_setup_post_type()`. Shared helpers: `uts_link()` (wordpress.org/GitHub/video URLs), `uts_register_build()` (registers a `build/` entry from `build/*.asset.php`), `uts_youtube_id()`, `uts_format_default()`, and the admin view helpers `uts_card_open()`/`uts_copy_field()`.
- `includes/class-db.php` (`UTS\DB`): saved shortcode instances in `{prefix}uts_shortcodes` (id, title, settings JSON, status publish/draft/trash, author_id, created_at/updated_at GMT). `install()` uses `dbDelta()`; `maybe_upgrade()` on `plugins_loaded` re-runs it when option `uts_db_version` is older than `DB::VERSION` (bump `VERSION` whenever the table changes; activation hooks don't run on updates). Static CRUD: `get()`, `query()`, `count()`, `insert()`, `update()`, `delete( $id, $force )`, `duplicate()`; errors are `\WP_Error` with an HTTP `status`. An instance stores **only the options it changes** (`sanitize_settings()` = `Settings::sanitize( $settings, true )`) plus `category` (must be an existing `uts_category` slug). Single items are cached (group `uts`); every write flushes them. Public wrapper: `uts_get_shortcode( $id )`.
- `includes/class-rest.php` (`UTS\REST`): REST namespace `uts/v1`. `/shortcodes/{id}/usage` (GET: posts whose content uses `[uts id="{id}"]`, max 20). `/shortcodes` (GET list with `X-WP-Total`/`X-WP-TotalPages`, POST → 201), `/shortcodes/{id}` (GET, PUT/PATCH, DELETE: trash, or `?force=true` → `{ deleted, previous }`), `/shortcodes/{id}/duplicate` (POST → 201 draft copy): need `REST::builder_capability()` = `manage_options`, filter `uts_builder_capability`. `/preview` (POST `{ attributes }` → `{ html }`; renders draft instances via the `uts_shortcode_instance` filter) and `/status` (GET: setup status + instance counts): need `edit_posts`. Arg schemas validate everything (the `settings` object comes from `Settings::schema()` without defaults, plus `category`, `additionalProperties: false`), so bad input is a 400 before any code runs. Item shape: `{ id, title, settings (object), status, shortcode, created_at, updated_at (RFC 3339), author { id, name } }`.
- `includes/class-assets.php` (`UTS\Assets`): frontend assets load only where `[uts]` is used (early via `has_shortcode`, fallback `Assets::enqueue_frontend()` inside the shortcode); admin assets only on `uts` screens; `register_jsx_runtime_fallback()` (see below).
- `includes/class-settings.php` (`UTS\Settings`): the `uts_settings` option (one flat object). `Settings::schema()` is the single source of truth: `defaults()`, `sanitize()` and the REST schema all derive from it (filter `uts_settings_schema`). Exposed on core `/wp/v2/settings` (needs `manage_options`); a POST replaces the whole object, so clients must send every key. Read values with `Settings::get( $key = null )` / `uts_get_settings()`. `Settings::sanitize( $value, $partial = true )` returns only the keys present (used for saved instances); the default fills every key with defaults. To add a setting, add it to the schema only. Option `uts_keep_data` (Settings → Advanced, default true) is registered separately, **not** in `uts_settings` (those keys are also shortcode attributes); it is stored as `'1'`/`'0'` by `Settings::sanitize_keep_data()` because a boolean false is saved as `''`, which `/wp/v2/settings` then returns as null. Read it with `Settings::keep_data()`.
- `uninstall.php`: plain script (runs without the plugin loaded, so no plugin classes); per site (looping over `get_sites()` on multisite). Always deletes `uts_activation_redirect`. If option `uts_keep_data` is off it also drops `{prefix}uts_shortcodes` and deletes `uts_settings`, `uts_db_version` and `uts_keep_data`; if it is on or was never saved (default), everything else is kept. Testimonial posts are always kept.
- `includes/class-cpt.php` (`UTS\CPT`): `register_types()` registers the `uts` CPT (title, editor, thumbnail, page-attributes for the Order field) and the hierarchical `uts_category` taxonomy.
- `includes/class-metabox.php` (`UTS\Metabox`): the "Client Additional" metabox, which stores post meta `uts_designation` (position & company), saved on `save_post_uts` (nonce, autosave and capability checks).
- `includes/class-shortcode.php` (`UTS\Shortcode`): `render()` runs a `WP_Query` on `uts` ordered by `menu_order ASC` and outputs the markup; `style()` and `slider_config()` build the CSS variables and Swiper config.
- `includes/class-menu.php` (`UTS\Menu`): registers Getting Started (`uts-getting-started`, `edit_posts`), Shortcode Builder (`uts-builder`, `REST::builder_capability()`) and Settings (`uts-settings`, `manage_options`), listed in `Menu::pages()`. All three only print `#uts-admin-root` (+ `<noscript>`); on `load-{hook}` `enqueue_app()` loads the `admin-app` build, `wp-components`, the frontend build (for previews) and the boot data `window.utsAdmin` from `Menu::app_data()` (version, allowed pages, schema, defaults, current settings, attributeDocs, categories, status, videoId, links, user capabilities). `activation_redirect()` opens Getting Started once after activation.
- `includes/class-admin-columns.php` (`UTS\Admin_Columns`): Photo / Position & Company / Order columns on the testimonials list, sortable Order, and the "Without photo" view (`?uts_photo=missing`, `pre_get_posts` NOT EXISTS on `_thumbnail_id`).
- `includes/class-getting-started.php` (`UTS\Getting_Started`): data only (the page is React): `setup_status()` (checklist), `attribute_docs()` (shortcode reference; add a description when adding a setting) and `video_id()` (tutorial video: placeholder until a YouTube URL is set in `uts_link('video')` or the `uts_getting_started_video` filter).
- **WordPress 5.8 support for React builds:** `@wordpress/scripts` compiles JSX for the automatic runtime, so React builds depend on `react-jsx-runtime` (core only since WP 6.6). `uts_register_build()` calls `UTS\Assets::register_jsx_runtime_fallback()`, which registers a small inline stand-in (`window.ReactJSXRuntime` on top of `wp.element.createElement`) when core doesn't have it. Mount React with `createRoot` when available (WP 6.2+), else `render()` (see `src/admin-app/index.js`). Keep both for any new React entry.
- `src/admin-app/`: the React admin app (one bundle for all three pages). `App.js` renders the shared `Header` and the page for `?page=`, navigates with `history.pushState()` (`router.js` keeps the URL, browser title and WP admin-menu highlight in sync; back/forward work) and guards unsaved changes (pages call `useApp().setDirty()`; leaving shows a Modal, `beforeunload` too). `api.js` wraps `uts/v1` and `/wp/v2/settings`; `data.js` exposes `window.utsAdmin`. Pages: `GettingStarted.js`, `Builder/` (`List.js`, `Edit.js`, `Usage.js`), `Settings.js`. Shared: `components/` (`Card`, `CopyField`, `Preview` = debounced POST `/preview` + `window.utsSlider.init()`, `VideoEmbed`, `Header`, `Field`). `fields.js` lists tabs/fields (labels, control type, `showIf`) for Settings and the Builder; min/max/enum/default come from the PHP schema. New setting = schema entry + one `fields.js` entry (+ an `attribute_docs()` line). The builder editor shows the value in effect (`{ ...globalSettings, ...instance }`), marks options the slider changes and can reset them; the preview sends only the changed options. Its sticky top bar holds Back, the name and Save Draft / Save; a new slider's name is pre-filled with `status.next_title` ("UTS #N") and an empty or untouched name is saved as "UTS #{id}" by `DB` (`default_title()`). `@wordpress/*` packages are in `dependencies` for lint only; at runtime they are WordPress externals.
- `src/frontend/`: Swiper init on every `.ucs-container.slider`, and masonry layout on every `.ucs-container.masonry` (a CSS grid; JS adds `.ucs-masonry-ready` and sets each card's `grid-row-end: span {height + gap}` on 1px rows, re-run by a ResizeObserver; without JS it stays a plain grid); `window.utsSlider.init( root )` (re)initializes both in markup added later. No autoplay under `prefers-reduced-motion`.
- Ticker layout is CSS only: `Shortcode::ticker_items()` outputs the items enough times for one screen-wide pass (`ticker_copies()`), then that pass again, with every copy `aria-hidden`; the track moves by -50% over `--uts-ticker-duration` (items × copies × `ticker_duration` seconds), pauses on hover/focus, and under reduced motion is a static scrollable row of the originals.
- `src/admin/`: styles only (Tailwind + SCSS) for every `uts` admin screen: list columns, the app header, checklist, guide, preview and video player.
- Tailwind CSS v4 is used for admin pages only (never the frontend, to avoid theme conflicts): no Preflight, prefix `uts` (write classes as `uts:flex`, `uts:md:grid-cols-2`), `important` (WP admin CSS is unlayered and would otherwise win). Sources scanned: `includes/**/*.php`, `src/admin-app`, `src/admin`. Custom colors: `wp-blue`, `wp-blue-dark`, `wp-border`, `wp-muted`, `wp-bg`. `postcss.config.js` adds Tailwind before the WordPress PostCSS preset.
- `readme.txt`: the wordpress.org readme (stable tag, changelog, FAQ).

## Shortcode

`[uts count="3" category="slug" type="slider|grid|list|masonry|ticker"]`, or a saved instance: `[uts id="5"]`. Precedence: **shortcode attributes > saved instance > global settings > schema defaults** (so `[uts id="5" autoplay="false"]` overrides the instance). The instance lookup is filterable (`uts_shortcode_instance`; only `publish` is rendered). An unknown, draft or trashed `id` outputs nothing for visitors and `<!-- uts: shortcode 5 not found -->` for users who can `edit_posts`. Defaults come from the global settings; every settings key also works as an attribute (e.g. `effect="fade" autoplay="true"`) and runs through `Settings::sanitize()`. Empty attributes are ignored.
- Slider options are passed to JS as JSON in `data-uts-config` (`Shortcode::slider_config()`, filter `uts_slider_config`). Colors, radius and grid columns are inline CSS variables (`Shortcode::style()`): `--swiper-theme-color`, `--uts-text`, `--uts-bg`, `--uts-radius`, `--uts-columns`, `--uts-columns-md`. The SCSS uses them with the 1.0.x values as fallbacks.

- The wrapper is `section#ucs-container-{type}.ucs-container.{type}`, and items are `.ucs-item`. Note that markup/CSS classes use the `ucs-` prefix while PHP uses `uts_`. Keep them consistent with the existing code.
- Fields in `fields.js` can have `layouts: [ ... ]` to show them in the Builder only for those layouts (`grid_columns`: grid and masonry; `ticker_duration`: ticker).
- Slider mode adds the Swiper classes (`swiper`, `swiper-wrapper`, `swiper-slide`) and `.swiper-pagination`.
- Every `.ucs-container.slider` initializes, so multiple sliders per page work. The first instance of each type keeps the ID `ucs-container-{type}`, later ones get `-2`, `-3`, ...
- If a testimonial has no featured image, `assets/images/quotation.png` is used instead.


## Conventions

- PHP code lives in classes, one per file: `includes/class-{name}.php` holds `UTS\{Name}`. The file name is `class-` + the class name in lowercase with `_` → `-` (`Admin_Columns` → `class-admin-columns.php`, `Getting_Started` → `class-getting-started.php`); acronyms stay uppercase in the class name (`CPT`, `DB`, `REST` → `class-cpt.php`, `class-db.php`, `class-rest.php`). Don't add a `uts-` prefix to file or class names (no `class-uts-cpt.php` / `UTS_CPT`); the `UTS` namespace already prevents clashes. Only `functions.php`, the main plugin file and `uninstall.php` stay procedural. Every class file starts with `namespace UTS;` then `defined( 'ABSPATH' ) || exit;`. New files must be `require_once`d from the main plugin file, and new components added to `Plugin::component_classes()`.
- Each class puts all its `add_action()`/`add_filter()` calls in a public `register()` method, with callbacks as `array( $this, 'method' )`. Constructors never add hooks.
- Inside `namespace UTS`, global **classes** need a leading backslash (`new \WP_Query()`, `\WP_Post`, `\WP_REST_Server`); global functions (`add_action()`, `uts_link()`) don't.
- Code needed in more than one place, and the public API, goes in `includes/functions.php` as global `uts_` functions wrapped in `if (!function_exists('uts_…'))`.
- Add `@since` / `@author Monzur Alam` docblocks on new classes and public methods.
- Use the text domain `uts`. All strings use `uts`.
- Sanitize input (`sanitize_text_field`, `absint`) and escape output (`esc_attr`, `esc_html`, `esc_url`). Verify nonces on save.
- Enqueue compiled assets with `uts_register_build()` (version comes from the asset hash).
- `tests/rest.php` covers the REST API: permissions per route for visitor/subscriber/editor (simulated with a `user_has_cap` filter, no users created)/admin, the `uts_builder_capability` filter, 400/404 errors, CRUD, list headers, duplicate, preview (incl. drafts) and status. It deletes the rows it creates.
- `tests/db.php` covers the saved shortcodes table: upgrade from 1.0.1, CRUD, sanitizing, cache, `[uts id]` precedence and unknown/draft/trashed IDs. It deletes the rows it creates. Run it the same way as the snapshot script.
- `tests/uninstall.php` runs the uninstall routine for keep data never saved / on / off, with backup and restore (it refuses to run when saved sliders exist).
- **Refactors must not change output.** `tests/snapshot.php` captures shortcode HTML, the settings API, admin pages, metabox, menu, CPT and assets. From the WordPress root: `wp eval-file wp-content/plugins/ultimate-3d-testimonial-slider/tests/snapshot.php compare` (exit 0 = identical); regenerate a reference only for intended changes, with `only=file.json`.

## Releasing

Commits are authored by Monzur Alam only: never add `Co-Authored-By`, "Generated with Claude Code" or any other AI attribution to commit messages or PR descriptions.

Bump the version in all three places: the `Version:` header and the `UTS_VERSION` constant in the main file, and `Stable tag` in `readme.txt`. Add a changelog entry to `readme.txt`. Release commits are titled `Release x.y.z`.
